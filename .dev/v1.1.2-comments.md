## Generic function/class/define/namespace/option names

Status: code fixed; one item needs an explanation. **Reply ready.**

> **Prefixes.** We renamed the remaining short `ptk` identifiers to the
> `pivot_performance_toolkit` prefix: the JavaScript globals passed through
> `wp_localize_script`, the REST namespace (now `pivot-performance-toolkit/v1`),
> the variables in the `advanced-cache.php` drop-in, and the related headers and
> labels. We also removed the bundled Symfony mbstring and PHP 8.3 polyfills (the
> plugin now requires the PHP mbstring extension and shows an admin notice if it is
> missing), which removes the global `Date*Exception`, `SQLite3Exception`,
> `Override` and `mb_*` declarations, and the vendored Composer autoloader classes
> are renamed to `PivotPerformanceToolkit_Autoloader_*`.
>
> **`WP_Object_Cache`.** `includes/Cache/object-cache.php` is an object-cache
> drop-in. WordPress requires a drop-in to define a class named `WP_Object_Cache`
> and the global `wp_cache_*()` functions under exactly those names, so they cannot
> be prefixed. The file is not loaded by the plugin: it is copied to
> `wp-content/object-cache.php` only when an administrator enables the file object
> cache, and it never overwrites another plugin's drop-in. This is now explained at
> the top of the file and in a new readme FAQ entry.

## Ajax endpoint URL

Status: code fixed. **Reply ready.**

What WP.org requires (from their review), and how each point is met:

| WP.org requirement | How the plugin meets it |
|---|---|
| Never assume the endpoint is `wp-admin/admin-ajax.php`; other configurations won't work. | The literal path is gone from `src/js/admin.js` and from the rebuilt `dist/admin-js.js`. |
| Determine the location with a function, e.g. `admin_url( 'admin-ajax.php' )`. | `Menu.php` sets `'ajaxUrl' => admin_url( 'admin-ajax.php' )`. |
| Execute that call in PHP and pass it to the JS with `wp_localize_script()` (also the place for the nonce). | The value is localized on the existing `pivot-performance-toolkit-admin-js` handle, as `pivotPerformanceToolkitAdmin.ajaxUrl`. |
| Refer to the endpoint in the JS through the localized variable. | `getAjaxUrl()` reads `pivotPerformanceToolkitAdmin.ajaxUrl`; all five `fetch()` calls go through one `ajaxFetch()` helper. |

Notes for us (not for the reviewer):

- Nonces: WP.org's example localizes one nonce. We keep a separate nonce per action in
  `data-ajax-nonce` attributes; the requirement is the URL, so this was left as is.
- If `ajaxUrl` is missing, the helper falls back to core's `window.ajaxurl`. If neither
  exists, `ajaxFetch()` rejects, so each caller's existing `.catch` shows "Request failed."
  rather than POSTing to the current page.
- WP.org's example variable `pivopeto-ajax` has a hyphen and isn't a valid JS identifier;
  ours is camelCase.

> **Ajax endpoint.** The admin script no longer hardcodes `/wp-admin/admin-ajax.php`.
> The URL is generated in PHP with `admin_url( 'admin-ajax.php' )` and passed to the
> script with `wp_localize_script()` (`pivotPerformanceToolkitAdmin.ajaxUrl`); all
> AJAX requests use that value, and the compiled `dist/admin-js.js` has been rebuilt.

## Unsafe SQL calls

Status: code fixed. **Reply ready.**

> **`DatabaseOptimizer::getTableStats()`**: the query no longer interpolates anything.
> It is now a constant `information_schema.TABLES` query with no `ORDER BY`; the
> requested sort column and direction are applied in PHP after the rows are fetched,
> using a fixed allowlist of columns, so no request-derived value can reach the SQL.
>
> **`optimizeTables()`**: the table name is now bound with `$wpdb->prepare( 'OPTIMIZE TABLE %i', $table )`
> instead of being concatenated with `esc_sql()`.
>
> The remaining queries in the class either have no variables or use `$wpdb->prepare()`
> placeholders; the only interpolated values are the core `$wpdb->posts`,
> `$wpdb->comments` and `$wpdb->options` table-name properties.
